# ECMAScript 2026

17th edition, ratified June 2026. Seven library additions, no new syntax. This edition is the clearest demonstration
that an edition number does not describe availability: `Array.fromAsync` reached Baseline widely available on 2026-07-25
having shipped in Chrome 121, while `Math.sumPrecise` only reached Baseline newly available on 2026-04-10 and is absent
from Node.js 26.

## Built-ins

- **Upsert** — `Map.prototype.getOrInsert(key, value)` and `getOrInsertComputed(key, callback)`, and the same pair on
  `WeakMap`. Replaces the `if (!m.has(k)) m.set(k, v)` double lookup.
- **`Iterator.concat(...iterables)`**
- **`Array.fromAsync(asyncIterable)`** — the async counterpart of `Array.from`
- **`Error.isError(value)`**
- **`Math.sumPrecise(iterable)`** — exactly-rounded summation, avoiding the drift of `reduce((a, b) => a + b, 0)`.
- **`Uint8Array` base64 and hex** — `Uint8Array.fromBase64`, `fromHex`, and the prototype methods `toBase64`, `toHex`,
  `setFromBase64`, `setFromHex`.
- **JSON source text access** — `JSON.rawJSON(text)`, `JSON.isRawJSON(v)`, and the third `context` argument to a
  `JSON.parse` reviver carrying `context.source`. Together they round-trip a number whose decimal form does not survive
  a double.

## Traps

- **`getOrInsertComputed` calls the callback only on a miss**, but the callback must not mutate the map: an insert
  performed inside it is overwritten by the return value.
- **`Array.fromAsync` is sequential.** It awaits each value before requesting the next, so draining an async generator
  of two 50 ms steps takes 100 ms. For concurrency use `Promise.all(arr.map(f))`; `fromAsync` exists for async
  iterables, not for parallelism.
- **`Error.isError` and `instanceof Error` disagree in both directions.** `Error.isError` is `false` for a plain object
  with `name` and `message`, and `true` for an error from another realm where `instanceof` is `false`. Prefer
  `Error.isError` in a `catch`.
- **`Math.sumPrecise` throws `TypeError` on a non-number element**, including a numeric string that `+` would have
  coerced.
- **`toBase64` pads even under `base64url`.** `new Uint8Array([251, 255]).toBase64({ alphabet: "base64url" })` is
  `"-_8="`; dropping the `=` needs `omitPadding: true` alongside the alphabet. Decoding an unpadded string with
  `{ lastChunkHandling: "strict" }` throws `SyntaxError`.
- **`JSON.rawJSON` rejects anything that is not valid JSON source for a single value**, and the produced object is only
  meaningful to `JSON.stringify`.
