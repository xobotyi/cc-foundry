# Use key-value lists for independent entries and tables only for comparison

- **Date:** 2026-06-02
- **Governs:** `plugins/*/skills/`, `plugins/*/CLAUDE.md`

Skills and plugin docs hold structured data that a model reads one entry at a time. Independent entries take key-value
or bullet lists, and tables stay for genuine comparisons, at the cost of a judgment against the column test for every
table.

## Decision

- **The column test.** Data where removing a column loses comparative meaning is a table; all other structured data is a
  key-value list, `- **key** — value`.
- **Independent entries** — skill registries, route-to-reference lists, tool references, configuration mappings, hook
  events, permission modes — use key-value or bullet lists.
- **Tables** hold genuine two-dimensional comparisons: decision matrices, feature comparisons, cost comparisons.
- **A table that fails the test** is converted when its file is written or reviewed.

## Why

- On lookup tasks, where each entry is read alone, key-value lists beat markdown tables by about 8.8 percentage points
  on identical content (benchmarks cited 2026-06-02; the source is not recorded).
- A wide table with long description cells overflows terminal and viewer widths: plugin `CLAUDE.md` skill registries
  carried Purpose cells of 200 and more characters.

## Consequences

- Every new or reviewed table needs a judgment against the column test, and two reviewers can disagree on it. Accepted.

## Rejected

- **Tables for any structured data** — about 8.8 points lower on lookup tasks, and long cells overflow the viewer.

## Revisit if

Measurement shows tables no worse than key-value lists on lookup tasks for the models in use. Confidence not recorded.
