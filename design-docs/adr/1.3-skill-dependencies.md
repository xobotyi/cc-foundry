# Express a skill dependency as hard or soft

- **Date:** 2026-06-02
- **Governs:** `plugins/*/skills/*/SKILL.md`, `plugins/*/CLAUDE.md`

Skills depend on other skills, and not every dependency is load-bearing. A hard dependency carries an explicit pointer
and a soft one is named in prose, at the cost of a tier judgment for every dependency.

## Decision

- **Hard** — skipping the other skill produces wrong output. The body carries an explicit pointer: a `<prerequisite>`
  block or a load-bearing step.
- **Soft** — the other skill only sharpens output, and the skill works without it. Prose names it, with no invoke
  pointer.

## Why

- An explicit "run X first" pointer on every dependency spends attention and tokens where nothing is load-bearing, and
  trains readers to ignore the pointer where it matters.
- The split is adapted from [mattpocock/skills](https://github.com/mattpocock/skills) ADR-0001.

## Consequences

- Every dependency needs a tier judgment. Accepted.
- `skill-engineering` dropped its dependency-tier section in its 2026-08-28 rebuild, with no reason recorded. The rule
  lives in this ADR and in the plugin `CLAUDE.md` files that apply it.

## Rejected

- **Every dependency hard** — pointers on dependencies that are not load-bearing train readers to skip all of them.

## Revisit if

The host resolves skill dependencies itself, so an explicit pointer stops being the reader's only cue. Confidence not
recorded.
