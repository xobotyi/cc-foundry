# Govern SKILL.md length by the deletion test, inside the durable window

- **Date:** 2026-06-02
- **Governs:** `plugins/*/skills/*/SKILL.md`

A SKILL.md has to do its job without its references, and compaction keeps only the first part of it. Length follows the
deletion test instead of a line cap, and a skill whose behavior outgrows the durable window splits, at the cost of
references that may go unread.

## Decision

- **No line cap.** The deletion test governs SKILL.md length: a line stays only if removing it changes output.
- **Behavioral self-sufficiency.** An agent that reads only SKILL.md does the job correctly. References hold lookup
  depth — catalogs, extended examples, edge cases — and never behavior.
- **The durable window.** Self-sufficiency holds within the first 5,000 tokens of the body, the part compaction
  re-attaches. A skill whose behavior does not fit splits instead of growing past the window.
- **Deliberate ceilings** for one skill carry a stated reason: `handoff` stays under 200 lines because it runs when
  context is nearly full.

## Why

- A hard cap forces behavioral rules out of SKILL.md into references the agent may never read.
- Defect density rises continuously with size, and after auto-compaction Claude Code re-attaches only the first 5,000
  tokens of each skill, so the tail of a long body is not durable however behavioral it is (skill-engineering rebuild,
  2026-08-28).

## Consequences

- Reviews judge a SKILL.md by self-sufficiency and the deletion test, not by line count.
- A split leaves depth in a reference that may go unread. Accepted.

## Rejected

- **A cap of about 100 lines with the overflow in references** — pushes behavior into files the agent may never open.
- **Bodies past the window when every line is behavioral** — the tail does not survive compaction.

## Revisit if

The host keeps more than the first 5,000 tokens of a skill through compaction, or reads references reliably. Confidence
not recorded.
