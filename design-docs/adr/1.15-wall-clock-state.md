# Keep the wall clock's anchors in the mod, the turn end per session in its store

- **Date:** 2026-11-11
- **Governs:** `plugins/wall-clock/hooks/`
- **Pinned by:** `plugins/wall-clock/tests/register.test.ts`

wall-clock ran a Node script from three command hooks and derived every figure from the tail of the session transcript.
It is a mod that takes its anchors from engine events: the turn start and its own ticks in memory, the turn end in its
store under the session id. The cost is a store write per turn and no `away` where that store holds nothing for the
session.

## Decision

- **A mod, and nothing else.** `plugins/wall-clock/hooks/hooks.json` names one hooks module and no command hook. The
  plugin runs no process and needs no runtime besides Claude Code.
- **Anchors from engine events.** The module takes the start of a turn from `turn.start` and the time of its last tick
  from its own writes, per conversation: the main one and each subagent's. It reads no transcript.
- **The turn end belongs to one session.** A main `turn.complete` writes its time to `$.store` under the session id,
  and `away` comes from the key of the current session id alone. No session reads another session's turn end. The
  module deletes a turn end older than 30 days at `session.start`.
- **No anchor, no figure.** Where the module holds no anchor, a tick carries the time alone. Where the model reads a
  context later than the module writes it, the module writes no tick.

## Why

- The user's instruction: "the wall clock plugin can be the code mod instead of the node plugin. lets migrate it"
  (2026-11-11). The command hooks made Node.js 26 a requirement
  ([ADR 1.13](/design-docs/adr/1.13-plugin-script-runtime.md)) and started a process on every prompt and tool batch.
- The user's ruling on `away`: "ok, persist it (the important part that it should not persist between sessions)"
  (2026-11-11).
- A mod gets no transcript path: only `classic.*` events carry `transcript_path`, and a managed-settings policy passes
  those past a mod outside the managed tier ([ADR 1.14](/design-docs/adr/1.14-sef-delivery.md)).
- Probe mods loaded with `--plugin-dir` on Claude Code 2.1.319 under the Team-org `cc-plugin-sec-default` (2026-11-11)
  received `session.start`, `prompt.submit`, `turn.start`, `tool.call`, and `turn.complete`, and read the host's time
  zone from `Date`. `$.session.id()` stayed the same across `claude --resume` and changed under `--fork-session`, and a
  `$.store` value written in one process was read in the next.
- The transcript scan saw 256 KB, so a burst of tool output cost a tick its elapsed figure and its throttle. Anchors
  from events have no window.

## Consequences

- A forked session, a session continued on another machine, and a session resumed after 30 days carry no `away` on
  their first prompt; the script computed it from the transcript. Accepted.
- The engine has no tool-batch event, so a tick follows a tool result. With a period of 0, parallel calls of one batch
  each carry a tick. Accepted.
- Under a managed-settings policy a compaction gets no note from a mod outside the managed tier, as in ADR 1.14.
  Accepted.
- The plugin needs a Claude Code that loads mods, verified on 2.1.319 only, and the tick period moved from an
  environment variable to a `userConfig` field, so its 3.0.0 is a breaking release. Accepted.

## Rejected

- **Reading the transcript through `$.fs`** — the module has no path to it under a managed-settings policy.
- **The turn end in memory alone** — the first prompt of a resumed session then has no `away`, where the gap is longest.
- **One turn end for all sessions** — a new session would report the time since another session's turn.
- **A tick on a prompt typed while a turn runs** — the API docs of 2.1.319 say `prompt.submit` settles when the prompt
  is queued behind the running turn, so the stamp would be old when the model reads it.
- **`Date.now()` as the time source** — the test kit mocks `$.clock` alone, so the anchors could not be tested.

## Revisit if

A mod outside the managed tier gets the transcript path, or `$.session.id()` stops being stable across a resume.
Confidence medium: probes on one build, and the timing of a queued prompt comes from the docs, not from a session.
