# Keep plugin metadata in plugin.json and only catalog fields in the marketplace entry

- **Date:** 2026-10-26
- **Governs:** `.claude-plugin/marketplace.json`, `plugins/*/.claude-plugin/plugin.json`

Each plugin's version, description, and other metadata had two copies, one in `plugin.json` and one in its
`marketplace.json` entry, and Claude Code reads each copy for different fields. `plugin.json` holds the only copy, and
the entry holds only the fields `plugin.json` cannot hold, at the cost of a listing that shows no version before
install.

## Decision

- **plugin.json holds the metadata.** A plugin's `.claude-plugin/plugin.json` holds its version, description, author,
  homepage, repository, license, keywords, and every other field that `plugin.json` accepts.
- **The entry holds the catalog fields.** An entry in `.claude-plugin/marketplace.json` holds `name`, `source`,
  `category`, and `tags`, and other fields only where `plugin.json` cannot hold them. A field that both files accept
  goes in `plugin.json`.
- **A version bump changes `plugin.json` only.**

## Why

- Claude Code takes the version from `plugin.json` and every display field from the entry, so a stale copy goes
  unnoticed on either side. 6 of 21 entries had a description or keywords that differed from `plugin.json` (2026-10-26),
  under a written rule to keep the two in sync.
- The Claude Code docs say not to set the version in both places
  ([host-marketplace](https://code.claude.com/docs/en/plugins/host-marketplace.md#release-a-new-version)).
- For a relative-path source, Claude Code reads `plugin.json` from the marketplace clone before install, so an entry
  without display fields still lists the `plugin.json` description, and the install caches at the `plugin.json` version
  (verified on Claude Code 2.1.310, 2026-10-26).

## Consequences

- `claude plugin list --available --json` shows no version for a plugin that is not installed, because that listing
  reads the version from the entry only (2.1.310). Accepted.
- No check enforces the rule yet; the repository integrity check adds one (#42).

## Rejected

- **Both copies, kept in sync by hand or by a check** — the docs advise against the second version, and every metadata
  edit touches two files.
- **The entry as the only copy, with no `plugin.json`** — a plugin loaded with `claude --plugin-dir` has no entry, so it
  would run without its version and description.

## Revisit if

A plugin moves to a source other than a relative path (`github`, `git-subdir`, `url`, `npm`, `archive`). For those
sources, listings show only the entry's fields until install, so the display fields would have to return to the entry.
Confidence high while every source stays relative.
