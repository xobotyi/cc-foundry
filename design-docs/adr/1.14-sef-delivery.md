# Deliver the Skill Enforcement Framework from a mod

- **Date:** 2026-11-11
- **Governs:** `plugins/skill-enforcer/hooks/`

skill-enforcer injected its framework and reminders from classic command hooks that ran a Node script. It is a mod: a
hooks module that Claude Code loads itself, at the cost of requiring a Claude Code that loads mods and of losing the
compaction handling for a mod outside the managed tier.

## Decision

- **A mod, and nothing else.** `plugins/skill-enforcer/hooks/hooks.json` names one hooks module and no command hook.
  The plugin runs no process and needs no runtime besides Claude Code.
- **Engine events that reach a user-tier mod.** The reminders go out through `prompt.submit` and `tool.call`, the two
  context channels a managed-settings policy leaves to a mod outside the managed tier. The framework rides on
  `prompt.submit` for the same reason. `session.compact` adds the compaction instructions and renews the framework where
  it arrives; the reminders do not depend on it.

## Why

- The command hooks made Node.js 26 a requirement ([ADR 1.13](/design-docs/adr/1.13-plugin-script-runtime.md)) for a
  plugin whose output is six constant strings. The user's reason for the change: "it will bring the major improvement
  of not-depending on the node" (2026-11-11).
- A command hook is a new process per event and holds nothing between events, so a reminder cannot depend on what the
  session did. A mod keeps state for the process.
- A probe mod loaded with `--plugin-dir` under the Team-org `cc-plugin-sec-default` on Claude Code 2.1.319 (2026-11-11)
  delivered context to the model through `prompt.submit`, `tool.call` (main loop and subagent), and
  `$.session.append`. Its `prompt.compose`, `skill.prompt`, `session.compact`, and `classic.*` hooks were skipped.

## Consequences

- The plugin needs Claude Code 2.1.287 or later, and its 3.0.0 is a breaking release. Accepted.
- Under a managed-settings policy, a compaction gets no SEF instructions from a mod outside the managed tier, and the
  framework returns only at the next process start, `/clear`, or resume. The command hooks handled both. Accepted: every
  reminder carries its full rule, and a mod seated in the managed tier receives `session.compact` (one headless run on
  2.1.319, 2026-11-11).
- The mods API is early access and its events move between releases. Accepted.

## Rejected

- **Command hooks that `cat` static payload files** — they remove the Node requirement, and keep one process per event
  with no state. Whether `cat` runs on every platform Claude Code supports is unknown.
- **A mod plus one classic `UserPromptSubmit` command hook** — one `hooks.json` holds both and both deliver (probe,
  2.1.319), but `prompt.submit` already reaches a user-tier mod, so the command hook adds a process and nothing else.
- **The framework as a `prompt.compose` section** — skipped for a mod outside the managed tier.
- **The framework through `$.session.append` at `session.start`** — it delivers, but `session.start` fires once per
  process and never for `/clear`, so a second mechanism would still carry the framework into a cleared conversation.

## Revisit if

A managed-settings policy stops delivering `prompt.submit` or `tool.call` context from a mod outside the managed tier,
or starts delivering `session.compact` to it. Confidence medium: one probe on one build.
