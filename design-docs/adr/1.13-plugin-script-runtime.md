# Write plugin scripts as TypeScript that Node 26 runs directly

- **Date:** 2026-10-28
- **Governs:** `plugins/*/**/*.mts`, `tsconfig.json`, `vite.config.ts`

Plugin hooks, the status line, and the scripts skills invoke ran as JavaScript typed by JSDoc, which the type checker
and the type-aware lint rules could only half read. Every such script is an `.mts` file of erasable TypeScript that Node
26 runs with no build step, at the cost of declaring every user on an older Node unsupported.

## Decision

- **TypeScript, run by Node.** A script that Claude Code runs through `node` — a hook, the status line, a script a skill
  invokes — is erasable TypeScript run by Node's type stripping. The repository builds nothing for it, and `tsc` and the
  lint rules check it exactly as they check `src/`. A mod that Claude Code loads itself, such as
  `plugins/plugin-rollcall/`, is not such a script.
- **`.mts`, never `.ts`.** An installed plugin carries no `package.json`, so a `.ts` file there would fall back to
  syntax detection while the repository's own `package.json` makes it an ES module. `.mts` runs as an ES module in both
  places.
- **Node 26 is the floor.** A plugin script uses any API Node 26 ships, and the README of every plugin that ships a
  script states Node.js 26 as a requirement.
- **Effects run only under `import.meta.main`.** A script exports its logic and performs I/O only when it is the entry
  point, so its tests import it.

## Why

- Type stripping is Stable from Node 24.12 and 25.2 and needs no flag
  ([Node docs](https://nodejs.org/api/typescript.html), read 2026-10-28).
- The development tooling types every file against `@types/node` 26, so a floor below 26 would hold only by discipline:
  nothing would flag a 26-only API in a plugin script (the user's decision, 2026-10-28).
- As JavaScript, plugin code ran with `checkJs` off and with the unsafe-type and readonly-parameter lint rules disabled.
  The status line crashed on an absolute path because an index read returned `undefined` (fixed in `96b040b`), a read
  that `noUncheckedIndexedAccess` types as possibly undefined in TypeScript.

## Consequences

- Node 24 was Active LTS until 2026-10-20 and is maintained until 2028-04-30, so most users fall below the floor when it
  lands. Each plugin that ships a script took a major version for it. Accepted.
- Nothing checks the Node version at run time: below 22.18 Node refuses an `.mts` file unless a flag enables type
  stripping, and on 22 or 24 a script fails where it first reaches a 26-only API. Accepted.
- The Node docs mark `import.meta.main` Stability 1.0, early development (read 2026-10-28), so a Node release may change
  it. Accepted.

## Rejected

- **JavaScript with JSDoc types** — the type checker read none of it with `checkJs` off, and the crash above reached
  users.
- **A build step that compiles to JavaScript** — a plugin installs from the repository tree as it is, so the output
  would be committed beside every source and drift from it.
- **A floor of Node 24.12** — type stripping is Stable there, but no tool would stop a 26-only API.
- **`.ts` with a `package.json` per plugin** — one more file in every plugin to state what the extension states.
- **Comparing `realpath(argv[1])` with the module path to detect the entry point** — it exists only for a Node without
  `import.meta.main`, which the floor rules out.

## Revisit if

Claude Code runs plugin scripts under a runtime other than the user's `node`, or Node drops `import.meta.main` or type
stripping. Confidence high for both while Node marks type stripping Stable.
