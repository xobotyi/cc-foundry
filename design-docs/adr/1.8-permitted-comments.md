# Permit exactly five kinds of comment

- **Date:** 2026-08-24
- **Governs:** `plugins/the-coder/skills/coding/references/comments.md`, `plugins/the-coder/skills/coding/SKILL.md`

A comment filter cannot hold when the model supplies both the comment and the verdict on it. The default is zero
comments and five enumerated kinds may exist, at the cost of a closed set that keeps drawing requests for a sixth.

## Decision

- **The closed set.** Five kinds may exist, and nothing else is written: doc comments on public symbols, the
  justification on an escape hatch, `shortcut: <ceiling> — <upgrade trigger>`, `constraint: <fact>`, and
  `why?: <hypothesis>`. Kinds are properties, not syntaxes; the `coding` skill's `references/comments.md` states each.
- **Commentary only.** Comment syntax a tool parses — build tags, `// Output:`, linter and type-checker directives,
  JSDoc types, codegen pragmas — is program text and outside the policy.
- **Rename before commenting.** A comment whose payload fits in an identifier is a naming defect. The limits on the
  rename live in the `coding` skill's `references/naming.md` alone.
- **Provenance gates every WHY.** A reason the agent holds is stated plainly; a reason inferred by reading is marked
  `why?:` or omitted.
- **A routing ladder replaces delete-only** — name, test, doc comment, rule document, architecture doc, marker, drown.
  Drown is the default verdict and is silent.
- **The codebase-conflict rule inverts for comments.** A comment-heavy convention neither licenses new comments nor
  authorizes stripping existing ones; repair stays within the files edited and the symbols read.
- **A sixth kind amends this ADR**, never only the skill.

## Why

- "Comment the non-obvious WHY" reads as an instruction to write a comment, and a model asked to find a non-obvious why
  finds one in every function: each rule of the filter judged a comment already decided on.
- A WHY recovered by reading code is a guess, since intent leaves no trace in source, and a confidently wrong reason
  survives review and is never re-checked.
- The daScript house workflow strips comments mechanically after a rescue pass, and its "cave with no comments"
  experiment marks inferred purpose as hypothesis, where `why?: unknown` outranks a plausible invention
  (`daslang.io/blog/no-comment.html`).
- `constraint:` exists because an external fact filed in an architecture doc is invisible to the person editing the line
  it constrains, who deletes the guard and ships the bug.

## Consequences

- Compliance is checkable: a review agent or a search can audit a closed set.
- Every single case for a sixth kind looks like the deserving exception. Accepted.
- On classic-prompt models the default prompt still permits a free-form WHY comment, so the skill states the override.

## Rejected

- **A filter: comment the non-obvious WHY** — the model supplies both the candidate and the verdict, so the filter never
  holds.
- **A "genuinely useful comment" escape hatch** — that judgment is the mechanism the closed set removes.
- **Delete-only** — an agent with nowhere to put a fact hoards it in a comment.

## Revisit if

A fact that must sit at the code recurs and fits none of the five kinds. Confidence not recorded.
