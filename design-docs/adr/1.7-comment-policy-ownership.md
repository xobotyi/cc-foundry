# Let the coding skill state comment and documentation policy in full

- **Date:** 2026-08-17
- **Governs:** `plugins/the-coder/skills/coding/`, `plugins/the-coder/output-styles/`,
  `plugins/ai-helpers/output-styles/`

Agents running cc-foundry's coding artifacts narrated code in comments and wrote change history into doc strings, and no
cc-foundry artifact held a comment policy. The `coding` skill states the policy in full as its own rules, so it binds on
models whose system prompt carries none, at the cost of overlapping the default prompt on models whose prompt does.

## Decision

- **One home.** The `coding` skill states comment and documentation policy in full, as its own rules, never as deltas
  against the default system prompt. What a comment may say is [ADR 1.8](/design-docs/adr/1.8-permitted-comments.md).
- **The reader is the test.** A comment or doc line that gives the next reader nothing the code already gives is waste.
  A convention that demands a doc is not a reader, so compliance never justifies a line.
- **Docs state the current contract**, at the length the caller needs, with no history and no changelog. A deprecation
  notice states the contract that holds now.
- **No copies in the styles.** The output styles scope density and route rationale to the response, the commit message,
  or an ADR; they carry no copy of these rules.
- **Placement stays with the language skills**, which decide the symbols that require a doc; this policy governs the
  content.

## Why

- The default system prompt's no-comments rule sits in its `# Doing tasks` section, which lean-prompt models never
  receive, so the output-style flag `keep-coding-instructions` changes nothing for them. Verbatim text, gate, and model
  roster: `plugins/ai-helpers/skills/output-style-engineering/references/coding-instructions.md` (2026-08-17).
- `the-writer` declared code comments out of scope and pointed at `the-coder`, which had no policy, while `coding`, the
  language skills, and the styles held three instructions about writing comments and none about whether they should
  exist.

## Consequences

- On lean-prompt models the skill is the only comment policy.
- On classic-prompt models the default prompt permits a free-form non-obvious-WHY comment, which
  [ADR 1.8](/design-docs/adr/1.8-permitted-comments.md) forbids, so the skill states an explicit override.
- The policy is pinned to a behavior of Anthropic's default prompt that can change without notice. Re-deriving
  `coding-instructions.md` against a newer prompt includes checking the overlap.

## Rejected

- **Relying on the default prompt's rule** — lean-prompt models never receive it.
- **A copy of the rules in each output style** — rules held in two places drift apart.

## Revisit if

The default system prompt carries a comment policy on every model in use. Confidence not recorded.
